WASA KASUR V12 - R2 PHOTO SETUP / IMPORTANT LIMITATIONS

1) Cloudflare Dashboard > Workers & Pages > WASA Store API > Settings > Bindings.
2) Add an R2 bucket binding:
   Variable name: BUCKET
   R2 bucket: WASA Store
3) Open Edit Code, replace Worker code with cloudflare-worker.js from this package, Save and Deploy.
4) Test in browser: open https://wasa-store-api.wasanafees.workers.dev/ . It should say:
   WASA photo service chal raha hai
5) App photo uploads are now routed to this Worker for:
   - Officer field photos
   - Officer profile photo updates (where supported by current Admin flow)
   - Admin activity photo replacement
   Cloudinary photo upload calls were removed from the Admin/Officer pages.

IMPORTANT SECURITY WARNING:
- This photo Worker currently allows public uploads and public photo reads. It has no login/session authorization, quota, or abuse protection. Do not treat this as a secure production private-photo service until authenticated upload/download authorization is implemented.
- CORS '*' is not authentication.
- Worker stores photos in R2 only. It does NOT migrate app login, users, consumers, activities, forms, messages, notifications, or other Firestore collections to D1.
- The Admin and Officer apps still use Firebase/Firestore for those records and login in this interim package. Firebase must NOT be disabled or deleted yet; doing so would break the app and may lose access to data.
- Cloudflare-only migration is NOT complete. It requires a full D1 schema/API/auth migration and verified export/import of existing data. This package deliberately preserves the current Firestore data flow while routing photo files to R2.
- No Cloudflare account deployment was performed by this package build. Upload/deploy the Worker script in the dashboard as above.
